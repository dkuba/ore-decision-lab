# Ore Decision Lab

**Interactive Process Decision Lab — публичный исследовательский PoT**. Четыре полностью синтетические золоторудные пробы, инженерные правила назначения исследований, первичные искусственные протоколы и интерактивное сравнение технологических альтернатив.

![status](https://img.shields.io/badge/data-100%25%20synthetic-0b8b81) ![qualification](https://img.shields.io/badge/industrial%20validation-not%20performed-C38748)

> **Не программный продукт для проектирования фабрики.** Данные и результаты опытов вымышленные. Литература поддерживает методологию исследований, но не квалифицирует численные коэффициенты извлечения, стоимость и области применимости данной руды. Нет независимой промышленной технологической экспертизы.

## Быстрая демонстрация для первого посетителя

Откройте сайт без регистрации и найдите блок **«Проверьте сами · 60 секунд»**. Два нажатия основной кнопки последовательно демонстрируют: изменение экономического лидера при изменении содержания Au с 0,80 до 1,60 г/т и отказ объявлять подтверждённое решение при противоречивой модели потерь. Все числа — синтетические; программа не делает промышленных рекомендаций. Подробности и сценарии проверки: [`docs/FIRST_VISIT_UX.md`](docs/FIRST_VISIT_UX.md).

## Что работает

- Один интерактивный экран в стиле **Scientific Light**, адаптированный для смартфонов.
- Четыре типа руды **A–D**: свободное золото, сульфидное золото, окисленная бедная руда и крупное золото.
- Различие **гипотез исследования** (правила минералогии) и **извлечения** (только по отдельным учётным продуктам синтетических опытов).
- Контрольные опыты CIL/CIP, гравитация с доводкой и CIL хвостов, флотация → POX/BIOX → CIL, кучное → ADR.
- Для руды C: ползунок **Au 0,60–1,60 г/т** и переключатель `constant_recovery` / `constant_residue` с показом расхождения второй гипотезы с крайними испытаниями.
- Принудительный `out_of_scope` при содержании вне испытанного интервала (напр., 1,85 г/т).
- Независимые переключатели отсутствия минералогии, отсутствия технологических испытаний и допущения о пригодности площадки.
- Детализация: стадийные коэффициенты, измеренные Au в продуктах, баланс direct feed vs calculated head, QA невязка, источник SYN-P01–12, формулы.
- План испытаний в состояниях: `available`, `needed`, `not_indicated`, `blocked_constraint`.
- Две глубины объяснений: **Руководителю / Технологу**. Основной интерфейс RU/EN; исходные протоколы остаются в оригинале.
- URL с параметрами без аккаунтов, аналитики, cookie-трекеров и загрузки документов.

## Быстрый старт

Нужно: Node.js 20+, Python 3.10+ (только для сборки статики), TypeScript 5.9.3.

```bash
npm install --global typescript@5.9.3
npm run test
npm run serve
```

Открыть `http://localhost:8000/`.

Пример сценария: `http://localhost:8000/?ore=C&grade=1.28&model=constant_recovery&heap_site=1`.

Проверка `npm run test` компилирует TypeScript, собирает каталог `dist/` и запускает unit-тесты через встроенный `node:test`, включая **14 опубликованных Python-контрольных векторов**. Нет npm runtime-зависимостей.

## GitHub Pages

Формат репозитория — `https://github.com/dkuba/ore-decision-lab`.

1. Код уже находится в `main`. Тесты запускаются при каждом PR и push в `main`.
2. В GitHub открыть **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Каждый push в `main` запускает сборку и тесты. При их успешном завершении workflow пытается опубликовать `dist/`; проверка оператора блокирует выпуск при пустых или неверных контактных данных.
4. Сведения оператора уже заданы в `public/site_config.json`: **Кубарев Дмитрий Владимирович**, **dkubarev@ya.ru**. Это публичные контактные данные сайта.

5. Дополнительная переменная GitHub Actions не требуется: релиз запускается только из `main` после успешного `verify` и проверки контактов.
6. Запустить workflow заново через **Actions → Verify and publish Ore Decision Lab → Run workflow** или отправить новый commit в `main`. Проверить статус отдельного задания `Publish to GitHub Pages`.

Тогда GitHub Actions дополнительно проверит оператора и контакт и опубликует `dist/`. После успешного деплоя адрес по стандартной схеме будет `https://dkuba.github.io/ore-decision-lab/` (при отсутствии кастомного домена). Вплоть до прохождения workflow нельзя считать этот адрес действующим.

**Причина gate:** `scripts/check_publication.py` предотвращает выпуск анонимного сайта, а условие workflow не допускает деплой из PR или других веток. Первичное включение Pages в Settings — отдельный шаг владельца репозитория.

## Достоверность и расчёты

`src/engine.ts` — независимый порт логики Python-пакета **literature-audited-candidate-1**. Для лабораторного разделения:

\[R_{split}=Au_{concentrate}/(Au_{concentrate}+Au_{tailings})\]

Для схемы с извлечением из концентрата:

\[R_{float+oxidation}=R_{flotation}\cdot R_{oxidation+CIL}\]

Для гравитации + доводки + CIL хвостов:

\[R_{gravity}=R_{split}\cdot R_{finishing}+(1-R_{split})\cdot R_{tail\,CIL}\]

Учебная денежная величина (не NPV):

`USD/t = Au(g/t) × synthetic_price(USD/g) × route_recovery − synthetic_cost(USD/t)`.

`constant_recovery` для C интерполирует опыты при 0,6, 0,8 и 1,6 г/т. `constant_residue` использует постоянное содержание Au в хвостах из центрального опыта, **но противоречит крайним точкам**; этот вариант никогда не становится квалифицированным победителем. Интервал близких результатов ±0,50 USD/т — условная UX-политика, не статистический доверительный интервал.

**Проверка качества:** по лабораторным продуктам проверяется независимая невязка относительно анализа питания с *учебным* допуском ±5%. Подозрительные повторы исключаются отдельно, а полностью утраченная промежуточная точка запрещает делать новый ранг посредством интерполяции. Обозначения статусов см. `docs/IMPLEMENTATION_PLAN.md`.

## Границы и следующая итерация

Не реализованы: авторизация, пользовательские загрузки, промышленный solver, 3D-блочная модель, полноценный учёт рециркуляции и фаз, модели оборудования, CAPEX/NPV, проверка представительности на реальной руде, независимое инженерное заключение. Отсутствие этих функций — **преднамеренное ограничение PoT**, а не скрытое обещание.

Литературный аудит: [`docs/LITERATURE_ENGINEERING_AUDIT.md`](docs/LITERATURE_ENGINEERING_AUDIT.md), источники и ограничения: `public/data/literature_register.json`.

## Права и безопасность

Право на самостоятельную публикацию/коммерциализацию заявлено владельцем идеи; этот исходный проект не предоставляет лицензию и не оценивает юридические документы. Перед публикацией убедиться, что владелец вправе открывать код и синтетические протоколы. **Не загружайте в этот репозиторий закрытые геологические данные, ключи, персональные сведения или исходный oracle.**

Контакт с пользователем организуется через `mailto:` после указания адреса в site_config — сервер не хранит заявки. Пока оператор не указан, интерфейс предлагает копировать нейтральное описание будущего пилота, не выдавая отсутствие контакта за отправленную заявку.
